## 阅读建议

- **刚接手** → 先读《项目交接文档》，尤其是第 11 章「已知问题」和第 12 章「README 勘误」
- **要改某个 Agent** → 读该 Agent 的专属文档
- **要跑起来** → 交接文档第 2 章「快速上手」
- **只想看该修什么** → 交接文档第 14 章「后续演进建议」（已按安全 / 功能 / 架构排好序）

## 🔴 跨 Agent 的共性问题（四处文档独立发现，建议一起修）

这几条不在单个 Agent 内闭环，散落在各文档中容易漏，故在此汇总：

| 问题 | 表现 | 出处 |
|------|------|------|
| **长期记忆整体失效** | `should_trigger_summary` 恒为 `False`（求值时 `dialogue_count` 恒为奇数）+ QA 侧 UPSERT 缩进错误 → **QA 完全不写库**；Interview 缩进正确但 `summary` 列恒为 `NULL` | 交接文档 §11.3 · interview §12.10 · qa §14.1 + §14.5 |
| **简历数据越读（IDOR）** | `_fetch_resume` 无归属过滤 + `resume_review_id` 零校验 → 任意学员可读他人简历 | 交接文档 §11.13 · interview §12.9 · resume §15.21 |
| **全项目无角色鉴权** | `api/v1/` 从未用 `role` 判断；学员可调 `/exam/confirm` **自己发布成绩**、可看全租户待确认批改 | 交接文档 §11.14 · exam §14.7 |
| **`fallback_used` 是死字段** | 四个 Agent 都声明了该字段，但全仓库**唯一写入点是 `resume/nodes.py:432`，且硬编码为 `False`**（不是判断结果）→ 任何 Agent 中都恒为 `False`，降级不可观测 | 交接文档 §11.4 · interview §12.5 · qa §14.2 · exam §14.4 |
| **`MemorySaver` 进程内内存** | 重启丢历史；多 worker 下 HitL 的 `/confirm` 路由不到持有 checkpoint 的进程，会话可永久卡死 | 交接文档 §11.1 · exam §14.3 |
| **Exam 无超时兜底** | 后台挂死则状态永卡 `ai_processing`（Resume 有 15 分钟超时，Exam 没有） | 交接文档 §12 勘误 · exam §14.11 |
